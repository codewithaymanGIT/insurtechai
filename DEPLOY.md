# Deploying InsurTechAI

The site is one Node service: the API and the built frontend on one origin. It needs a database that
survives restarts. Two routes:

- **Render + Turso (free):** the simplest way to a public link. Steps below.
- **Docker:** for Fly.io, Railway or a VPS with a persistent volume. See the end.

Estimates, the insurer comparison and the claim frequency model work without sign-in. Sign-in needs either
Google sign-in or SMTP email to be configured, because production never prints codes to a log.

## 1. Database on Turso

1. Sign up at [turso.tech](https://turso.tech) and create a database (any name, nearest region, e.g. Mumbai or Singapore).
2. On the database page, copy its **URL** (`libsql://...turso.io`) and create a **token**.

The migrations and sample portfolio are applied automatically on each deploy (the seed only runs when
the database is empty).

## 2. Web service on Render

1. Push the repo to GitHub.
2. In [Render](https://render.com): **New → Blueprint**, pick the repo. It reads `render.yaml`.
3. Fill in the variables Render asks for:

| Variable | Value |
|---|---|
| `APP_ORIGIN` | Your service URL, e.g. `https://insurtechai.onrender.com` (no trailing slash) |
| `DATABASE_URL` | The Turso URL |
| `DATABASE_AUTH_TOKEN` | The Turso token |
| `GOOGLE_CLIENT_ID` | Optional, see below |
| `SMTP_*`, `EMAIL_FROM` | Optional, see below |
| `GEMINI_API_KEY` | Optional; a **new** key, with billing enabled if real users will type into the chat |
| `ADMIN_EMAILS` | Your email, to see the usage page |

`AUTH_SECRET` is generated by Render. Don't change it later: that would sign everyone out and make
existing 2FA secrets unreadable.

4. Deploy. When it's live, `https://<service>.onrender.com/api/health` returns `{"status":"ok"}`.

On the free plan the service sleeps when idle, so the first visit after a quiet spell can take up to a
minute. Upgrade the plan to keep it awake.

## 3. Turn on sign-in (pick one or both)

**Google (easiest):** in [Google Cloud Console → Credentials](https://console.cloud.google.com/apis/credentials),
create an OAuth client ID of type *Web application*, add your service URL under *Authorized JavaScript origins*,
and set `GOOGLE_CLIENT_ID`.

**Email codes via Gmail:** turn on 2-Step Verification on the Gmail account, create an
[App Password](https://myaccount.google.com/apppasswords), then set `SMTP_HOST=smtp.gmail.com`,
`SMTP_PORT=587`, `SMTP_USER=<the address>`, `SMTP_PASS=<the app password>`, `EMAIL_FROM=InsurTechAI <the address>`.

## Docker

```bash
docker build -t insurtechai .
docker run -p 4000:4000 -v insurtechai-data:/data \
  -e AUTH_SECRET="$(openssl rand -hex 32)" \
  -e APP_ORIGIN=http://localhost:4000 \
  insurtechai
```

The container migrates and seeds on start, stores SQLite in the `/data` volume, and serves the site on port 4000.
On a public host, set `APP_ORIGIN` to the public HTTPS URL and `TRUST_PROXY=1` behind a load balancer.

## Before sharing the link
- Rotate any API key that has ever been pasted into a chat, commit or screenshot.
- Set `ADMIN_EMAILS` and check `/insurers/usage` works for you.
- Add the link to the README and the GitHub repo's *About* box.
